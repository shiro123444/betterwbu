# BetterWBU

武汉商学院报销系统的 Chrome 扩展，当前版本 **0.13.26**。

## 0.13.26：收款账户名称直接输入

修复账户名称获得焦点或输入时自动打开已保存收款人弹层、将输入焦点移入模板搜索框的问题。名称现在始终可在原框直接编辑，只有主动点击右侧“选择已保存收款人”箭头才搜索模板；仍通过原有受校验的桥接逻辑回填完整收款信息。等待描述返回期间已离开原输入框时，不再打开过期弹层。

验证：291 项回归测试通过。本地合成表单检查连续输入中文及英文时焦点仍在名称框、无模板弹层且开户行不被自动替换；主动点击箭头后的模板搜索和选择保留。未修改真实收款账户，未触发 AI、暂存或提交。

## 0.13.25：识别状态收起与面板伸缩

识别状态默认只显示数量摘要，放在票据工具栏下方；按需展开后在面板内滚动，长文件名省略显示并可悬停查看。文件夹栏右边界可拖动调整宽度，识别详情底边可拖动调整高度，均设置上下限并保存尺寸偏好；支持方向键微调、Home/End 到边界、双击恢复默认。窗口缩小时自动限制尺寸，空间不足便收起识别详情，重新放大后恢复原先展开状态与尺寸。标题、工具按钮和筛选区可自动换行或局部滚动，手机宽度改为横向文件夹区域。

验证：290 项回归测试通过。使用本地合成的 40 条识别结果，检查默认收起、状态更新保持滚动位置、拖动上下限、双击恢复，以及 760×600 和 390×700 的响应布局。真实独立票据页面仅临时加载布局源码验证文件夹栏；未上传票据或触发 AI、暂存、提交。识别任务的真实上传流程未重跑。

## 0.13.24：发票夹布局和加载状态

管理发票夹与报销选票共用左侧文件夹导航，可搜索全部文件夹并查看票数，不再局限于原生三个标签。右侧统一显示当前文件夹、票据总数、刷新、筛选、排序、批量编辑和添加票据；新建和重命名使用带校验的表单弹窗，删除仍使用原系统的确认和回收规则。原票据卡片、分页、选票、上传和详情保留原生处理。

区分首次加载、慢响应、接口失败与真实空文件夹；外层页面在嵌入发票夹就绪前显示连接提示，等待过久提供重新加载入口。仅对文件夹与票据列表两个只读请求设置最长20秒等待，保留原来更短的超时，不重试写入操作。新版票据区使用局部状态提示，避免重复加载遮罩挡住文件夹切换。旧插件连接失效时停止定时请求，避免反复抛出同一异常。关闭视觉或票据优化时恢复原生布局。

验证：286 项回归测试通过，最后的文件夹定向测试 7 项通过。真实独立票据页面临时加载新版源码，读取到95个文件夹，验证了搜索、有票和空文件夹切换、新建空名称及同名校验、取消和重命名弹窗；没有实际创建、重命名、删除文件夹或上传票据。外层工作台嵌入加载状态及失败重试有本地覆盖；重新加载扩展后的跨页面完整流程仍需实页复验。

后续本机排查捕获到 Chrome `InsecureLocalNetwork`：HTTP 页面访问学校内网票据接口时被浏览器拦截，独立票据页可正常读取。用户在原报销页执行 `Ctrl+Shift+R` 后确认恢复；这支持缓存或页面安全上下文状态参与触发，尚未证明具体浏览器内部机制。该恢复不归因于 UI 更新，插件不关闭本地网络安全检查，也不更改代理。

## 0.13.23：参加会议报销单票据生成

新增对已检查的“参加会议报销单”模板的支持，沿用原生参加会议活动、费用分类、金额字段和票据关联结构。支持票据生成明细、单人自动全额归属、精确到分的关联使用金额与重复更新；明确的会议注册费、会议报名费、会议服务费及会务费自动识别为原生“会议服务”，项目、服务机构和内容仅取自票据已识别字段。其他单据类型继续受限，会议单不套用常规差旅补贴预设。入口禁用时增加模板范围提示。

修复空白会议单首次生成时，内层费用组件也携带 activitys 标记而覆盖外层表单实例的问题：仅将同时具备原生 form 和 activityOptionList 的组件作为活动入口。费用行仍由原系统处理函数初始化，保留失败回滚和撤销。

验证：277 项自动测试通过。当前会议草稿以临时加载同一新版票据源码的方式，实页生成并重复更新 5 条明细：城市间交通费 1246 元、住宿 700 元、改签退票费 93.50 元、会议服务 2500 元，合计 4539.50 元；五行均自动归属同一人员，各含一条原生票据关联，使用金额与行金额一致。铁路类型缺失的三张票按已经核对的原件手动确认分类，没有推测恢复 OCR。网络观察期间未出现 AI、暂存或提交请求；结果只在当前页面，尚未验证保存后的后台票据详情。当前临时模块在刷新后失效，持久使用需重新加载 0.13.23 扩展；未保存的页面明细应由用户决定如何保留。

## 0.13.22：跨分类更新时迁移原票据关联

修复“改签费原在城市间交通费中，改成改签、退票费后被报重复使用”的问题。在“更新所选分类”模式中，同一活动内完全由本次所选发票支撑、金额与关联一致的原费用行，会随改分类迁移；保留该原分类中的其他车票、其他活动和未选补贴。预览明确列出迁移行数、来源与目标分类，并在总额中扣除旧行，避免重复计入。追加模式继续检查原关联；混有未选票据、辅助凭证、关联标识不一致或手填金额的原行须先核对，不自动删除。更新失败和撤销均恢复原行、关联及金额。

真实页面验证：0.13.21 的改签票可选择“改签、退票费”，改签票和住宿无需点击均分便分别自动归属同一人员 93.50 元、700 元。随后复现旧交通费关联导致的重复使用拦截。0.13.22 的新算法在当前真实表单上只读核算：迁移交通费原行 93.50 元、保留费用 1966 元，生成改签费和住宿后总额仍为 2759.50 元。该只读核算没有安装热补丁、修改页面费用、暂存或提交真实单据；新版实际写入仍需重新加载扩展及页面后验收。273 项自动测试通过，覆盖真实问题结构的生成、重复更新、预览、回滚、撤销及混合行保护。

## 0.13.21：单人自动归属与铁路费用核对

从票据生成明细时，票据载明唯一人员便自动按全额归属；住宿备注中的明确“入住人：姓名”也参与识别。其余未记名票据仅在本批票据能确认唯一人员、且没有含糊人员信息时复用该人员。手动输入单个归属人员后直接分配全额，不再要求逐张点击“按人均分”。多人继续显式确认分摊，保留已编辑的人员和金额，不把购方、销方或经办人当作出差人员。

费用分类增加读取票据备注、费用类型及 processDetail 的费用说明；明确“改签费 / 改签手续费 / 退票费 / 退票手续费”归入“改签、退票费”，普通“改签后车票”仍按票价分类，票价和手续费混合时要求核对。铁路电子客票未返回票面费用类型时不再默认选中交通费，改为提示对照原件选择分类，不依据金额、发票号码猜测，也没有新增图片 OCR 或外传影像。

真实页面只读排查确认：一张 93.50 元原件写有“改签费”，但学校返回的结构化识别数据缺失该文字，旧插件遂归入交通费；这张票仍需在生成预览中手动选择“改签、退票费”。本版补足已返回字段的分类并提示缺失信息，不能声称恢复了学校没有返回的 OCR 内容。269 项自动测试通过，覆盖单人免点击、多人核对、精确金额与原生发票关联。未修改、暂存或提交真实单据；安装本版后需重新加载扩展和报销页面再验收。

## 0.13.20：WebVPN 消息来源兼容

真实页面验收发现，深信服 WebVPN 会在主世界将 `MessageEvent.origin` 还原成上游直连地址，而隔离世界仍看到代理地址，导致界面已加载但预检、收款资料及票据桥接不响应。现在兼容已确认的代理域名到 `http://wsbx.wbu.edu.cn` 的来源映射，并继续验证发送窗口，不接受其他门户或相似域名。扩展不会修改代理脚本、关闭来源校验或使用通配消息目标。

验证：263 项自动测试通过。重新加载 0.13.20 后，在学校 WebVPN 的 `:8118` 实页确认登录身份识别、报销列表、现有单据的页面与后台明细预检、内嵌发票夹和票据影像详情正常响应；后续流程单据保持只读。实页验收未修改、暂存、上传或提交财务数据；同步填报、关联写入及提交拦截由自动测试覆盖，未在正式单据中执行。

## 0.13.19：校园网与 WebVPN 双入口

保留校园网 `wsbx.wbu.edu.cn`，新增学校 WebVPN 报销域名 `wsbx-wbu-edu-cn.webvpn.wbu.edu.cn`，支持实际入口的 `:8118` 端口。工作台的主世界和隔离世界脚本、内嵌票据夹、扩展弹窗、收款资料和模板存储、填报备份及 AI 请求保护均适配这两个入口。只匹配这两个具体域名，不申请整个 WebVPN 或其他学校业务系统的访问权限。

WebVPN 保留原页面路径，因此沿用学校自身的请求客户端和当前页面来源，不把接口、票据地址或窗口消息切回直连域名；发送窗口校验保持不变，消息来源兼容见 0.13.20。登录跳转中的临时 `ticket` 不需要配置，也不写入源码、日志或测试。更新后请重新加载扩展并刷新 WebVPN 报销页；Chrome 如提示新增站点权限，需允许该报销域名后才能注入插件。

自动测试覆盖直连和 WebVPN 的入口识别、端口、工作台与票据夹脚本加载、主世界适配、收款字段、弹窗、后台备份与保护恢复，并拒绝相似域名及其他门户地址。

## 0.13.18：左侧填报助手与侧栏入口

填报状态、明细预检、同步及恢复移出信息管理，统一放到左侧第三个主栏目“填报助手”。展开侧栏后可选择“状态与预检”或“同步与恢复”，打开独立面板；收起时点击第三个图标即可打开工具。状态面板默认只读检查，不自动填报、恢复、暂存或提交。信息管理保留收款资料、基本模板和设置。

侧栏顶部改为整行图标加文字的伸缩按钮，展开时显示“收起侧栏”，收起时保留居中图标和展开提示。继续转发学校原生伸缩事件，保留原菜单、路由与财务字段；关闭视觉优化时原生入口恢复，填报助手仍可使用。

验证包含第三栏位置、原生菜单重建后去重、关闭恢复、独立只读请求、宽窄屏边界及键盘操作。合成浏览器预览位于 `tests/browser/react/fill-review.html`，使用当前构建产物，不连接学校后台。已检查 1440px 和 390px 宽度，并在重新加载扩展后的学校页面验证第三栏入口、费用行票据关联以及当前页面和后台已保存明细的预检。

## 0.13.17：排除未使用分类的空白占位行

真实草稿验收发现：原系统会在过路过桥、保险、燃油等未使用分类中保留空白行，旧预检把这些行误判成金额无效，并导致费用合计显示未读取。现在忽略只有默认人员或行号的空白占位行；已填日期、说明或关联票据却没有金额的行仍需核对。非数字金额仍报告异常，后台合计的空白占位行按零处理。

## 0.13.16：交通费与补贴明细预检

“信息管理 → 设置 → 检查当前单据”分别显示当前页面（含未保存修改）和后台已保存明细的问题，定位到活动、分类、行号。城市间交通费、改签退票费检查原生票据关联、发票行和使用金额，并在本单票据金额已知时检查重复使用；影像区已上传的附件不能代替费用行关联。用餐及市内交通补贴检查补贴地、标准、天数、起止日期、扣减金额及同人日期重叠，按当前原生标准核算，不猜测或补造学校标准。

原生提交前拦截这些已知的明细问题，保留错误原因；未完成的草稿仍可暂存，也不改变原生生成流程。补贴预览明确说明“省外普通地区”等估算选项不能代替原生补贴地，生成后须逐行选择地区并核对原生计算结果。插件不会自动修改本次申请金额、重新关联发票或提交单据。

已用匿名场景复现两项未关联发票和两项补贴依据缺失，覆盖只读检查、当前与后台差异、精确到分的关联余额、重复关联、日期与扣减、提交拦截及草稿可保存。源码已更新；学校页面的新版插件需重新加载后验收，最终票据有效金额及稽核由学校系统判定。

验证：232 项检查通过。0.13.12 重载后的真实列表中搜索字段为 16px，真实只读详情值为 16px，稽核报告按钮为 42px。0.13.13 的菜单定位及分页补丁在真实只读页以临时 CSS 验证，菜单伪元素为 static，分页完整落在容器内；本地补充验证 390px 下无页面横向溢出。没有改变单据字段或执行业务按钮。

## 0.13.11：Base UI 与原生控件衔接

修复包裹在 `p`、`span` 等元素中的原标题残留；新标题和行操作完成 React 挂载后才隐藏原生入口，挂载尚未完成时保留原入口。整颗行操作按钮统一接管，原生重绘替换按钮时重新绑定，禁用的父级不会被子图标绕过。纯文本按钮的旧文字不再与新图标、说明叠加，关闭优化时恢复原文本节点和事件。

原生财务字段继续保留原来的 Vue 节点、值、校验和事件。补齐旧版 Ant Design 的选择框、日期框、金额框、下拉选项、复选框及确认窗口外观，使用与 Base UI 一致的字体、边框、圆角和焦点样式；为缺少命名容器的窄屏表单补上单列布局。没有修改报销金额、票据、审批或提交逻辑。

发票夹的独立页面及内嵌 iframe 也加载同一份组件主题，修复只有主报销页生效、票据页仍出现另一套控件与按钮说明的样式断层。

验证使用本地合成页面 `tests/browser/react/native-components.html`：嵌套标题、按钮外层、原生重绘、四类字段尺寸、行操作单次触发及窄屏布局。源码与构建产物已更新；学校页面仍需扩展重新加载后验收，不把本地预览当作所有实际页面已完成替换。

## 0.13.10：票据请求完整性保护

同一标签页切换报销路由后按实时 URL 校验备份及临时许可，拒绝不同草稿的请求。保存、提交或 AI 请求中的票据清单为空、或多页票据缺少子票时停止请求，避免费用关联存在但发票有效金额变成零；不伪造填报或审批状态。

## 0.13.9：区分填报记录、生成结果和审批状态

真实单据验证：AI 生成接口报错后，后台仍保留填报记录，之后原生提交成功进入待审批。这个现象不代表所有单据只触发一次就能通过，也不代表费用数据或打印报销单完整。插件不写入或伪造 `aiFlag`，不跳过后台稽核。

“一键同步填报”先只读检查当前单据的后台状态。已有填报记录时转为核对，不再调用 AI、不自动恢复或覆盖当前明细、不自动暂存或提交。生成失败与填报记录分别保留；只有新的、尚无记录的待提交草稿才执行备份和正常生成流程。离开表单路由时拒绝使用仍在内存中的旧草稿，已提交页面只读。

信息管理 → 设置新增“检查当前单据”，显示后台状态、费用及实收合计、违规及提醒数量，并对照已加载打印文本中的小写金额。打印文本尚未加载、无法访问或没有小写金额时显示未读取，不把未知当作零或通过。原始失败消息和稽核提醒继续保留；已提交单据不撤回、不改写。

本次真实后台确认待审批、总额与费用及实收合计一致，保险、住宿及其他费用金额规则通过；页面打印件却显示零金额和空明细，已记录为待排查的独立问题。只读核对算法已用该后台快照及视觉确认的打印金额验证；新版整套界面尚需扩展重载后验收。

## 0.13.8：原生填报失败识别与日期预检

原生后台可能在填报返回 `success:false` 后仍写入 `aiFlag:true`。兼容流程现在观察该草稿实际的原生 AI 接口响应，分别保存生成成功或失败结果；单凭 `aiFlag` 不再自动恢复并暂存。恢复后的再次打开也保留结果记录，旧版本没有确认记录的备份不会直接跳过生成。

同步前检查已加载票据的交通明细日期。发票头有开票日期、但 `air/processDetail` 某个交通行没有 `issueDate` 时明确指出对应票据和行号，不把开票日期猜作行程日期、不改写识别原件。缺失数据仍需原系统正常修订；没有编辑权限时需财务或厂商处理。

真实新草稿已触发原生 `ai-again`，返回附加产品票交通行日期缺失。后台稍后自行回到待提交，金额保持不变；只读查询已能解析两张附加产品票、抽查的保险及住宿关联。尚未确认完整稽核或最终提交成功，不把 HTTP 200、关联存在或 AI 标记当作报销通过。

## 0.13.7：一键填报兼容流程

信息管理 → 设置 → 填报兼容新增“一键同步填报”。先把当前用户、当前待提交草稿的核对明细备份到扩展本地存储，临时允许该标签页运行学校原生填报。读到后台返回的真实填报完成状态、且票据清单未变化后，自动恢复核对好的费用、分摊关联、收付款、经费及事前单信息，再通过原生事件发起暂存。已经完成填报且存在备份时直接恢复并暂存，不重复生成。异常、中断、身份或草稿切换、票据变化时停止，不自动提交。

正常路径不用重复手工填写原生 AI 表单。学校若返回行程补全、票据分类等必需确认窗口，仍由原生流程处理；插件不能猜测未核实内容，也不伪造 `aiFlag`、稽核或审批结果。备用“恢复核对明细”仅恢复页面，仍需暂存。备份不静默覆盖，按账户和草稿隔离；临时填报许可最多三分钟，完成、超时或切换草稿后恢复原拦截设置，无新增浏览器权限。

本地回归覆盖费用及关联恢复、真实完成状态校验、备份失败停止、一次性许可隔离及恢复、后台进程挂起后的许可清理、完整的一键生成与恢复暂存流程。真实页面已只读确认原生填报处理器可接入；尚未验收学校后台的一键填报、重新暂存后的票据有效金额或最终提交。

## 0.13.6：票据分摊状态与明细来源

同一名单仅变更逗号、空格或重复输入时保留已确认的分摊金额；实际变更人员后仍要求重新均分，并明确提示具体操作。已保存票据的识别详情尚未加载时显示等待详情，避免误报为非发票；详情到达后重新核对。普通增值税服务发票中的辅助乘机人记录不再被选为计价明细，关联实际的发票商品行。

均摊仍按所选发票金额守恒，不绕过原系统票审或稽核。更新分类会重新生成该分类的金额，手动核减过的本次申请额需单独核对预览，不能据此自动恢复为票面全额。回归覆盖 112.98、135.99 两张附加产品票的三人均分及每张关联使用额，不涉及修改已提交单据。

## 安装

1. 下载或克隆本仓库。
2. 打开 Chrome 的 `chrome://extensions/`，启用开发者模式。
3. 点击“加载已解压的扩展程序”，选择 `development/reimbursement-enhancer/extension`，该目录直接包含 `manifest.json`。

## 功能

票据生成现同时写入原生费用行关联，支持明确按人员分摊、保险按人员合并、住宿凭证以零使用金额挂到具名费用行。预览要求每张发票分摊金额守恒，追加检查已有使用金额；替换、撤销及失败回滚同时处理关联与金额。详见 [票据关联使用与验证](development/reimbursement-enhancer/scripts/票据关联使用与验证.md)。已提交单据不会自动修改；学校后台真实保存接受和稽核须在新草稿中验收。

- 统一表单、发票夹和报销详情布局，修复重复按钮和横向溢出。
- 发票夹确认时显示请求与预览更新状态，阻止重复确认。
- 从有效票据生成费用明细，支持分类、去重、更新所选分类和撤销；支付截图与辅助材料不参与发票合计。
- 根据明确的住宿起止日期预填差旅时间，核对人员、地区和适用条件后计算补贴。
- 保存收款资料和基础模板，支持银行字典及手填开户行。
- 加载反馈依据原生请求状态显示，支持减少动态效果；不会自动重复提交。

费用和补贴须由使用者核对。学校后台的稽核规则、审批结论及有效发票金额统计由原系统决定；插件的分类结果不代表后台稽核已通过。界面默认精简黄色提醒，保留阻断错误和原生稽核报告入口。
